Kong's official documentation is already fairly detailed, and readers should consult it first. This post is mainly a personal record, essentially a memo, so it may be missing a lot of detail.

First, there are many ways to deploy Kong Gateway. This post uses the simplest one: deploying the containers manually with Docker.

## Network

```bash
docker network create kong-network
```

## Database

Here we deploy a local Postgres container.

```bash
docker volume create kong-database-volume

docker run -d \
    --name kong-database \
    --network kong-network \
    -p 5432:5432 \
    -e "POSTGRES_USER=kong" \
    -e "POSTGRES_DB=kong" \
    -e "POSTGRES_PASSWORD=kongpass" \
    -v kong-database-volume:/var/lib/postgresql/data \
    postgres:16

```

Run the database migrations:

```bash
docker run --rm --network kong-network \
    -e "KONG_DATABASE=postgres" \
    -e "KONG_PG_HOST=kong-database" \
    -e "KONG_PG_PASSWORD=kongpass" \
    kong/kong:3.9.1 kong migrations bootstrap

```

## Kong Gateway

```bash
docker run -d \
    --name kong-gateway \
    --network kong-network \
    -e "KONG_DATABASE=postgres" \
    -e "KONG_PG_HOST=kong-database" \
    -e "KONG_PG_USER=kong" \
    -e "KONG_PG_PASSWORD=kongpass" \
    -e "KONG_PROXY_ACCESS_LOG=/dev/stdout" \
    -e "KONG_ADMIN_ACCESS_LOG=/dev/stdout" \
    -e "KONG_PROXY_ERROR_LOG=/dev/stderr" \
    -e "KONG_ADMIN_ERROR_LOG=/dev/stderr" \
    -e "KONG_ADMIN_LISTEN=0.0.0.0:8001" \
    -e "KONG_ADMIN_GUI_PATH=/manager" \
    -e "KONG_ADMIN_GUI_URL=http://yourdomain.com:8002/manager" \
    -p 80:8000 \
    -p 443:8443 \
    -p 8001:8001 \
    -p 8002:8002 \
    kong/kong:3.9.1

```

Note: the following environment variables are set so that Kong Manager can be reached through a public domain:
* KONG_ADMIN_GUI_PATH=/manager
* KONG_ADMIN_GUI_URL=http://yourdomain.com:8002/manager

Since we've configured a domain, we inevitably have to deal with the SSL certificate. Kong ships with the ACME plugin, which can issue a certificate for our own domain and refresh it automatically.


Open `http://yourdomain.com:8002/manager` in a browser to reach the Kong Manager UI and configure Kong from there. As shown below:

![kong-manager](/images/kong-manager.png)


## ACME Plugin

Issuing a certificate for the domain with the ACME plugin involves three main steps:
* Create an acme-service: a dummy service that handles the ACME Challenge and related work.
* Create an acme-route attached to the acme-service above.
* Create an acme-plugin. It is **global**, and this plugin implements the core ACME functionality.


### acme-service

![acme-service](/images/kong-acme-service.png)

As you can see:
* host: localhost
* port: 65535

Both are meaningless values.

### acme-route

![acme-route](/images/kong-acme-route.png)

Note:
* Uncheck **Strip Path**

### acme-plugin

![acme-plugin](/images/kong-acme-plugin.png)


Note:
* You can add one or more domains to the `domains` option
* Or you can select `Allow Any Domain`


At this point the ACME plugin is fully configured.


### Create SSL Certificate

You can trigger **certificate generation** through the Kong Admin API:

```bash
curl http://localhost:8001/acme -d host=yourdomain.com
```

After a few minutes you will see output like this:

```bash
{"message":"certificate for host yourdomain.com is created"}
```


Then under Kong Manager / Certificates you will see:

![acme-certificate](/images/kong-acme-certificate.png)


## Securing Kong Manager access via domain (SSL + Auth)

To access Kong Manager through a domain with SSL, a few configuration changes are needed:
* Change the Kong Gateway environment variables
* Create the Kong Manager service & route
* Create the Kong Admin service & route


### Change the Kong Gateway environment variables

* Change the `KONG_ADMIN_GUI_PATH` and `KONG_ADMIN_GUI_URL` settings
* Change the `KONG_ADMIN_LISTEN` and `KONG_ADMIN_API_URL` settings

For example:
```bash
    -e "KONG_ADMIN_LISTEN=0.0.0.0:8001,0.0.0.0:443 ssl" \
    -e "KONG_ADMIN_GUI_PATH=/kong-manager" \
    -e "KONG_ADMIN_GUI_URL=https://kong.yourdomain.com:443/kong-manager" \
    -e "KONG_ADMIN_API_URL=https://kong.yourdomain.com:443" \

```

Careful!!! **Do not redeploy after making the changes!!!** You need to wait until all of the following configuration is complete before redeploying.

### Configure the authentication plugins for Kong Manager

The Kong Gateway we use is the open-source edition, and Kong Manager is open-source as well, so by default there is no access control. With domain access enabled (which means the public internet can reach it), that is very dangerous.

To solve this, we can do the following:
* Enable an IP allowlist on the server so that only your IP can access it
* Add an authentication plugin to Kong Manager


We won't cover IP access control on the server here. We will focus on how to add authentication to Kong Manager.

In the previous sections we created services & routes for both kong manager & kong admin, so naturally our authentication plugins can go on these two services or routes. Since routes may be added to a service later, putting the authentication plugin on the service is a bit safer.

So which authentication plugin is the best fit? We use **Basic Auth** here, mainly because:
* Browsers support Basic Auth well and pop up the Basic Auth form wherever authentication is needed, so we don't have to change any part of the Kong Manager UI


Note: **if you run into problems configuring things in the Kong Manager UI, switch to the Kong Admin API — it can do anything!!!**


#### Configure the Basic Auth plugin

Add the Basic Auth plugin to the Kong Manager service:
![kong-manager-basicauth](/images/kong-manager-basicauth.png)


Add the Basic Auth plugin to the Kong Admin service:
![kong-admin-basicauth](/images/kong-admin-basicauth.png)


#### Configure the ACL plugin

The Basic Auth plugin alone is not enough, because as long as Basic Auth credentials exist anywhere else in Kong, those credentials can also log in and access Kong Manager, which is effectively a privilege escalation. To avoid this, we also need the ACL plugin to control which Basic Auth credentials can access Kong Manager.

Add the ACL plugin to the Kong Manager service:
![kong-manager-acl](/images/kong-manager-acl.png)


Add the ACL plugin to the Kong Admin service:
![kong-admin-acl](/images/kong-admin-acl.png)

The ACL plugin's **Allow** value here is the **Group Name**, which we will configure on the Consumer shortly.


#### Configure the Kong Manager Consumer

We create a new Consumer dedicated to Kong Manager, giving Basic Auth authentication a separate, distinguishable identity.

![kong-manager-consumer](/images/kong-manager-consumer.png)

Then we add the actual credentials to this Consumer:
* Configure Basic Auth Credentials; these can only be configured when the Basic Auth plugin is enabled
* Configure ACL Credentials; these can only be configured when the ACL plugin is enabled

![kong-manager-consumer-credentials](/images/kong-manager-consumer-credentials.png)



Configure the ACL Credentials:
![kong-manager-consumer-credentials-acl](/images/kong-manager-consumer-credentials-acl.png)

Note that the **Group Name** here must match the plugin.


Configure the Basic Auth Credentials:
![kong-manager-consumer-credentials-basicauth](/images/kong-manager-consumer-credentials-basicauth.png)

Set Username & Password to whatever you like, as long as it stays secure.


After configuring the Consumer Credentials, the list looks like this:
![kong-manager-consumer-credentials-all](/images/kong-manager-consumer-credentials-all.png)


#### Enable the plugins on the services

Just enable the plugins, for both the Kong Manager & Kong Admin services.


#### Redeploy Kong Gateway

All configuration is now updated. Redeploy Kong Gateway so that the environment variables take effect.


Visit in a browser: https://kong.yourdomain.com/kong-manager

The Basic Auth login form will pop up:
![kong-manager-basicauth-form](/images/kong-manager-basicauth-form.png)


Enter the Username & Password you set earlier to get into the Kong Manager UI.
